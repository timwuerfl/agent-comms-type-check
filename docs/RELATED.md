# Related work and how SwarmGate differs

Full citations are in `paper/refs.bib`. This note states, honestly, what already exists and what is new,
because "session types for LLM agents" stopped being an empty niche in 2026.

## Closest concurrent work (LLM agents + protocol discipline)

| Work | What it does | How SwarmGate differs |
|---|---|---|
| **ZipperGen** — Bollig, Függer, Nowak, *Provable Coordination for LLM Agents via Message Sequence Charts* (ISoLA 2026); + Causal Past Logic (ICFEM 2026). Lean 4. | Global MSC workflow → syntax-directed projection to per-agent programs that are deadlock-free by construction; projection correctness machine-checked in Lean 4. | The nearest neighbour. It is **correct-by-construction coordination for cooperative agents**: the local programs are *generated*, so agents are trusted to run them. SwarmGate is a **security reference monitor for untrusted/compromised agents**: our central theorem is enforcement against arbitrary adversaries, and we add runtime payload refinements, verified IFC, blame, and an attack evaluation. |
| **Concordat** — Sikaroudi, *Typed Sessions for LLM Agents* (arXiv 2610.37461, 2026). | Single-agent typestate enforced by masking the tools offered each turn; adversarial τ-bench evaluation. No proofs; multiparty projection is future work. | Same thesis ("the model can't be trusted to follow the protocol, so enforce it") but **one agent**, no multiparty projection, **no mechanised guarantee**. SwarmGate is multiparty, verified, and swarm-wide; Concordat's tool-masking is our "protocol-guided decoding", and it's a good empirical baseline. |
| **Pact** — Gopinathan et al. (Basis), *A Choreographic Language for Agentic Ecosystems* (CP@PLDI 2026). | Choreographies for LLM agents with game-theoretic constructs; endpoint-projection correctness is future work. | Choreography for self-interested agents; no mechanisation, no monitor, no security model. |
| **Ahoy/Kiko** — Joshi, Singh, Chopra, *LLMs Enacting Multiagent Interaction Protocols* (EMAS 2026). | LLM agents enact declarative **BSPL** information protocols; an adapter validates chosen messages before emission. | Protocol-enforcing adapter around LLM agents, from the MAS/BSPL tradition (information causality, not message ordering). No mechanised proofs, no adversarial security evaluation. A credible alternative *protocol model*; we discuss why MPST suits a brokered swarm. |
| **CervellaSwarm "Lingua Universale"**, **llmsessioncontract** (OSS/PyPI, 2026). | MPST-flavoured DSLs + runtime checkers for AI agents; one advertises a "Lean 4 bridge". | Superficially the same pitch, but unreviewed, with an undocumented/opaque trusted base and no security threat model or evaluation. The differentiator is rigour: a stated enforcement theorem with a clean TCB, kernel-checked per-protocol proofs, and attack experiments. |
| **ControlValve** — Jha, Triedman, Wagle, Shmatikov, *Breaking and Fixing Defenses Against Control-Flow Hijacking in MAS* (ICLR 2026). | Generates a permitted control-flow graph for the MAS before reading untrusted content and enforces compliance (CFI + least privilege). | Closest *security* precedent for "only talk along declared edges", but the graph is LLM-generated per task with no formal protocol language and no proofs. SwarmGate's edges are a verified session protocol with ordering, payload types, IFC and temporal properties. |

## Foundations we build on

- **Multiparty session types**: Honda–Yoshida–Carbone (POPL 2008; JACM 2016); "less is more" (Scalas & Yoshida, POPL 2019). We use an **automata** presentation (global LTS), following implementability-via-automata results (Alur–Etessami–Yannakakis; Li–Stutz–Wies–Zufferey, CAV 2023; Castro-Perez–Ferreira–Jongmans, POPL 2026), to keep every check decidable.
- **Mechanised session types / choreographies**: Zooid (PLDI 2021, Coq), sound-and-complete projection (Tirore–Bengtson–Carbone, ITP 2023), mechanised liveness (Keskin–Yoshida–van Glabbeek, ITP 2026), Mech (Lean 4 choreographies, 2026). SwarmGate is the Lean-4 **monitor** counterpart: the proof obligation is the gate, not the agents, and the verified definitions run as the runtime.
- **Runtime monitoring of session types**: Bocchi–Chen–Demangeon–Honda–Yoshida (TCS 2017); monitor soundness in Lean for the P4/NEST setting (ECOOP 2026). SwarmGate states and mechanises monitor soundness/transparency/blame for an **agent runtime whose principals are LLMs**.
- **Enforceable security policies**: Schneider (execution monitors enforce safety properties); Ligatti–Bauer–Walker (edit automata). This is why protocol conformance — a safety property — is monitor-enforceable, and why liveness needs timeouts/crash branches.
- **Blame**: Gommerstadt–Jia–Pfenning (session-typed contracts). We give a Lean theorem that the monitor blames the actual deviating sender and never an honest one.
- **Information flow + sessions**: Capecchi–Castellani–Dezani-Ciancaglini–Rezk; Derakhshan–Balzer. We connect this line to **prompt-injection propagation** in LLM swarms (dual-LLM / CaMeL / plan-then-execute as a verified protocol property).

## LLM multi-agent security (the threat model)

Attacks we target structurally: Prompt Infection (Lee & Tiwari 2024) and infectious jailbreaks (Agent Smith, Gu et al. 2024); arbitrary-code execution in MAS (Triedman–Jha–Shmatikov 2025); agent-in-the-middle (He et al. 2025); the MAST failure taxonomy (Cemri et al. 2025); the open-problems and risks agendas (Schroeder de Witt 2025; Hammond et al. 2025). Defences with structural guarantees we relate to: CaMeL (Debenedetti et al. 2025), design patterns for securing agents (Beurer-Kellner et al. 2025), AgentSpec, IsolateGPT. Benchmarks: AgentDojo, InjecAgent, Agent Security Bench.

**What protocol enforcement can and cannot do** (see also `THEORY.md §9`). Structurally prevented regardless of LLM behaviour: topology violations / worm spread, out-of-order actions (skipped approval), wrong-branch-owner (choice hijack), ill-typed/out-of-range payloads, impersonation/AiTM, replay, runaway loops/cost-DoS, and — via IFC — untrusted content reaching a privileged action. Not prevented by typing alone: semantic injection inside a free-text field, a compromised agent making a *wrong but well-typed* decision, specification errors, and anything outside the mediated channel (tool poisoning, model backdoors). SwarmGate's framing: protocol enforcement makes the **control plane** a verified property; the **data plane** is bounded by typed fields and a verified IFC check, not eliminated.
